## 目录职责 / Directory Responsibilities

- `public/assets/brand/`：预留的项目所有者第一方标识目录；当前成品不分发该目录下的位图，个人
  独立开发标识由 HTML 文本与 CSS 原生绘制。

  Reserved directory for first-party identity assets owned by the project owner. The current artifact does not distribute bitmaps from this directory; the independent-development identity is rendered natively with HTML text and CSS.

- `public/assets/primal-reference/`：界面直接引用的图片与 SVG。它们是运行依赖，不是研究附件。

  Images and SVG files referenced directly by the interface. They are runtime dependencies, not research attachments.

- `public/assets/primal-runtime/`：Spine、音频、字体、界面图集和流式资源清单。

  Spine assets, audio, fonts, interface atlases, and streaming-asset manifests.

- `public/THIRD_PARTY_NOTICES.txt`：随 Web 成品分发的前端开源依赖声明。

  Notices for front-end open-source dependencies distributed with the Web artifact.

- `asset-provenance.json`：机器可读的目录级权属状态和发布处理方式；该文件不进入 Web 成品。

  Machine-readable directory-level ownership status and release handling; this file is not included in the Web artifact.

`public/` 不允许存放 README、抓包、截图、测试夹具、设计过程稿、浏览器缓存、源码映射或密钥。
说明文档应放在 `web/` 或 `docs/`，原始取证材料必须保存在仓库外。

`public/` must not contain README files, traffic captures, screenshots, test fixtures, design-process drafts, browser caches, source maps, or keys. Documentation belongs in `web/` or `docs/`, and original evidentiary material must be kept outside the repository.

## 两层发布门禁 / Two-Layer Release Gate

1. `npm run assets:provenance-check` 校验公开目录没有夹带文档或证据文件，并确认所有受保护资源
   都被 `asset-provenance.json` 分类。

   `npm run assets:provenance-check` verifies that the public directory contains no bundled documentation or evidence files and confirms that every protected asset is classified by `asset-provenance.json`.

2. `npm run build:release` 根据本次构建产生的 `release-manifest.json`，要求仓库外提供
   `RELEASE_ASSET_APPROVAL_FILE`。审批必须覆盖所有受保护资源的精确路径、字节数和 SHA-256，
   同时包含审批引用、适用地域和有效期；缺失、过期或任一字节不一致都会失败关闭。

   Using the `release-manifest.json` generated by the current build, `npm run build:release` requires a `RELEASE_ASSET_APPROVAL_FILE` supplied from outside the repository. The approval must cover every protected asset's exact path, byte count, and SHA-256, and must include an approval reference, applicable territories, and validity period. A missing or expired approval, or any byte mismatch, fails closed.

哈希审批只能证明“本次获批的字节与成品一致”，不能替代授权链或商标注册证据。目前
`primal-reference/`、`primal-runtime/` 及 `favicon.ico` 的权属材料未存放在仓库中，因此在取得
可审计授权或完成自主素材替换前，不应将当前 Web 资源包对外宣称为可商业分发或全部原创。

Hash approval proves only that “the bytes approved for this release match the artifact”; it cannot replace an authorization chain or trademark-registration evidence. Ownership material for `primal-reference/`, `primal-runtime/`, and `favicon.ico` is not currently stored in the repository. Therefore, until auditable authorization is obtained or independently owned replacement assets are completed, the current Web asset package must not be represented externally as commercially distributable or wholly original.

## 资源变更 / Asset Changes

~~~sh
cd slots-game/web
npm run assets:provenance-check
npm run assets:generate-streaming-packages
npm run build
npm run build:assets-check
npm run build:bundle-check
~~~

新增、移动或替换资源时，必须同步更新运行时引用、资源清单、权属分类和外部精确哈希审批。
不能通过删除来源记录、降低清单覆盖率或把资源移到未保护目录来绕过发布门禁。

When adding, moving, or replacing assets, update runtime references, asset manifests, ownership classifications, and external exact-hash approval together. The release gate must not be bypassed by deleting provenance records, reducing manifest coverage, or moving assets into an unprotected directory.
